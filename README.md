# chatluna-plugin-livingdiary

LivingSystem 生态下构筑的 QQ 空间插件，提供动态发布、评论与回复能力。联动 livingmemory 插件实现 bot 的人格化日记记录与发布功能。

## 使用

在插件配置的 `allowUserIds` 中填入可以操作空间的 QQ 号。登录态取自实例中已上线的 OneBot 或 Milky 机器人；有多个账号时，用 `selfId` 指定要使用的空间。

发布命令、工具和日记在每次发布前向绑定机器人获取当前 Cookie，再提交一次动态。日记正文先保存在日记册中，发布结果单独记录。

| 命令 | 用途 |
| --- | --- |
| `qzone.status` | 查看空间登录态、最近一次日记的结果和自动互动的运行情况 |
| `qzone.feeds 3` | 读取机器人最近 3 条动态 |
| `qzone.feeds 3 -t 123456` | 读取指定 QQ 号的可见动态 |
| `qzone.publish 今天下雨了` | 发布到机器人的空间；同一条消息可附最多 9 张图片和多段 MP4 视频，也可以只发素材 |
| `qzone.delete <动态ID>` | 删除机器人的指定动态；`qzone.feeds` 在自身列表中显示 ID |
| `qzone.delete --recent 3` | 预览最近 3 条自身动态，由本人确认后删除（可选 1–10 条） |
| `qzone.digest` | 根据今天的记忆写一篇日记 |

白名单用户也可以说「删除你刚才那条猫图动态」或「删除最近两条动态」，机器人会调用 `qzone_delete`。工具按 ID 或最近条数直接删除。只有手动输入 `qzone.delete --recent` 才会展示清单，请在原会话 60 秒内回复「确认删除」或「取消」。两个入口都按选定的清单逐条执行；某条删除结果未核实时即停止，并列出剩余 ID。删除空间动态会保留日记册记录。删除工具独立于发布工具开关。

白名单用户可以直接说「看看你自己的动态」「看看好友动态」或「看看 QQ 123456 的动态」，机器人会调用只读工具 `qzone_list_feeds`。好友动态沿用 QQ 空间的展示顺序。每次默认读取 `feedsDefaultLimit` 条（初始值 5），可指定 1–10 条，再说「下一页」继续查看。关闭发布工具后仍可查看动态。

看到列表后可以继续说「看第一条的第二张图」「看看这段视频」或「只看视频封面」。机器人按原顺序选取对应编号，调用 `qzone_read_media`；只有选中的文件才会下载。支持图片或视频输入的对话模型直接接收对应文件，也可由支持该输入的 `@vision` 描述。静态封面单独标识。单次可读取一张不超过 15 MiB 的图片，或一段不超过 32 MiB 的 MP4。编号仅供原请求者在当前会话使用，失效后可重新查看列表。

开启 `enablePublishTool` 后，「工具」页会列出 `qzone_publish`。把自己的 QQ 号填入 `allowUserIds`，就可以在对话里让机器人发说说，例如「把这张照片发到空间，配文写『雨停了』」。发布时检查本次请求者本人的权限；白名单为空时无人可发。

发送图片和 MP4 视频后，可以直接说「把这些发到空间，自己配文字」。机器人填写正文，发布工具按当前会话的图片、视频编号读取原文件，一起发布为一条动态。也支持提供原文件链接。图片预览和视频封面不作为发布素材。

图片每张最多 32 MiB，网络读取时限 30 秒；视频每段最多 128 MiB，网络读取时限 120 秒。全部素材读取完成后提交一次，任一素材读取或格式校验失败即结束本次发布。含视频的动态按详情中的素材数量和视频 ID 确认完整送达。

如果提示无法确认是否发布成功，先用 `qzone.feeds` 核对，以免重复发布。

`qzone.feeds` 会在分享动态的配文下列出卡片标题、摘要和完整链接。封面由自动互动的看图流程读取，命令列表只显示文字。当前支持 SDK 已验证的移动端分享卡片结构。

## 每日日记

启用 LivingMemory，在 LivingDiary 配置中选择空间预设（`personaPresetId`）和写日记的模型（`mainModel`）。「每日日记」中有两个独立的开关，默认都开启：

- **定时撰写日记**（`enableDailyDigest`）：默认每天 23:50 开始，按服务器本地时间计算，可用 `digestTime` 调整。关闭后，白名单用户仍可发送 `qzone.digest` 手动写一篇。
- **将日记发布到 QQ 空间**（`publishDiaryToQzone`）：定时和手动写好的日记都会先存入日记册。关闭此项即可只保存、不发空间。

机器人使用 LivingMemory 中该预设的人设卡片写日记，没有卡片时使用预设的系统段原文。写作参考这个预设从今天零点到任务开始时新建、且仍然活跃的记忆。编辑旧记忆不会改变创建日期；Dream 合并或拆分生成的新条目按新条目的创建日期计算。默认最多使用最近 100 条，可通过 `digestMemoryLimit` 调整。当日没有记忆，或模型认为没有值得分享的内容，就跳过本次写作。

## 在 WebUI 里翻日记

打开 **LivingDiary → 日记**，点击书本左侧的「预设」便签，翻到扉页选择预设，即可从最近一篇往前翻，也可以指定日期。同一天写的多篇日记会分别保留。左页是日记正文，右页是写这篇时交给模型的全部记忆原文。

日记册默认跟随 WebUI 的深浅色。在预设扉页左页底部的「纸色」可以单独切换，选择会保存在当前浏览器。

在「插件配置」中可以直接设置空间账号、白名单、日记和自动互动；「插件使用指南」介绍如何写第一篇日记，以及各项设置和发布状态的含义。

## 自动评论和回复

在插件配置中选择空间人设（`personaPresetId`）和互动模型（`subModel`）。在「自动互动」的 `interactionAllowUserIds` 中填写希望机器人互动的 QQ 号。这份名单独立于命令白名单；默认名单为空，机器人不会主动互动。自动互动不需要 LivingMemory。

| 想让机器人做什么 | 怎么配置 |
| --- | --- |
| 主动评论好友新发的动态 | 开启 `enableFriendPostComment`，模型会根据动态内容决定评论或跳过。 |
| 回复自己空间下的新评论 | 将 `interactionMonitorPostLimit` 设为大于 0 的数，默认关注 10 条动态。机器人在好友动态下发过一级评论时，也会跟进该评论线程里的新回复。 |
| 只评论新动态，不跟进回复 | 开启好友动态评论，把 `interactionMonitorPostLimit` 设为 0。 |
| 允许与所有可见用户互动 | 关闭 `enableInteractionWhitelist`。 |

机器人上线后先记住已有的动态和评论，从下一轮开始处理新增内容。插件重启时重新建立起点，不补发停机期间的评论。默认每 60 分钟检查一次，每轮最多发起 5 次评论或回复，可分别调整 `interactionPollIntervalMinutes` 和 `interactionMaxWritesPerRound`。用 `qzone.status` 可以查看待处理数量、已受理和结果待核对的写入次数。

如果希望机器人看懂动态配图，可以选择支持图片输入的互动模型；使用纯文本互动模型时，也可以为 ChatLuna 的 `@vision` 角色配置读图模型。每次互动最多读取 9 张托管在 QQ 空间图片域名下的配图，单张上限 15 MiB，合计 45 MiB。GIF 按需抽帧，视频、音频和文件只提供类型、名称等信息。

分享动态会分别提供发布者配文、卡片标题、摘要和目标链接。分享封面标明来源后，追加在独立图片之后，复用上述看图能力与限额；封面读取失败时仍提供卡片文字。分享目标保持网页链接，互动流程不访问外站解析内容。

## 构建

在插件目录运行 `yarn build`。

调试页面时，保持模板项目的 `yarn start` 运行，在另一个终端进入 LivingDiary 目录执行 `yarn dev`。保存 `client/` 下的改动后，已打开的 WebUI 会自动更新。这个命令只监听前端。

## 发布

更新 `package.json` 中的版本号后，在插件目录运行 `npm run pub`。脚本会清理旧产物、重新构建，并将该版本发布到 npm 公共仓库。
